# Coding Reliability

## v0.1

The first 10 cases are primarily a schema-development exercise.

For self-checking:

- fully code each case once
- re-read the source before marking it `reviewed`
- after several days, re-code at least two cases without looking at the first coding
- note fields that produce inconsistent judgments

## Later versions

If another coder joins the project, double-code a meaningful subset before large-scale expansion.

Prioritise agreement testing for:

- attack category
- psychological mechanisms
- attribution basis
- attribution strength
- primary evidentiary gap

Disagreements should be used to improve definitions rather than hidden.

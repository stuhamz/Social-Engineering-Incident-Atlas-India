# v0.1 Pre-Publication Release Audit

Audit date: **16 August 2026**

## Outcome

**Green light for public GitHub release as a v0.1 methodology pilot.**

The release is suitable for publication as an open research repository provided it is described as a purposively selected ten-case pilot, not as a representative study of Indian cybercrime.

## Checks completed

### Source integrity

- 16 registered source records reviewed for structure and linkage.
- Each of the 10 incidents has at least one T1 judicial source.
- Core incident facts, loss figures, procedural posture, and material attribution claims were rechecked against the registered public sources.
- Source-stage language was reviewed to preserve allegations, defence claims, prima facie observations, and final judgments as distinct categories.

### Data consistency

- 10 unique case IDs.
- 16 unique source IDs.
- 10 screening-log records.
- Every `primary_source_id` resolves to the source registry.
- Controlled vocabulary and JSON schema include the pilot-added `family_impersonation` and `sextortion` categories.
- Validator passes with 0 errors and 0 warnings.

### Corrections made during audit

1. **SEIAI-0002 beneficiary-account count**
   - Previous value: 8
   - Corrected value: 7
   - Reason: the source lists nine transfers but only seven distinct beneficiary account numbers because two accounts were reused.

2. **SEIAI-0004 cross-border and reconnaissance coding**
   - Cross-border dimension changed from `yes` to `not_reported`.
   - Reconnaissance changed from `yes` to `unknown`.
   - Reason: Canada was part of the impersonation pretext, but the source does not establish an actual cross-border actor or how the impersonator learned the relative's identity.

3. **SEIAI-0009 reconnaissance and credential coding**
   - Reconnaissance changed from `yes` to `unknown`.
   - Credential compromise changed from `yes` to `unknown`.
   - Reason: account takeover is reported, but the source does not establish a separate reconnaissance process or the technical credential-compromise mechanism.

4. **SEIAI-0010 cross-border coding**
   - Changed from `unknown` to `not_reported` because no material cross-border element is described.

### Privacy and republication

A repository-wide scan found no long phone numbers, bank-account numbers, or email addresses reproduced in the Markdown/CSV research material. External source URLs remain in the source registry.

### Release documentation

- Public README rewritten for v0.1.
- Data licence resolved as CC BY 4.0.
- MIT retained for software.
- Pre-push working note replaced with release notes.
- Records promoted from `draft` to `reviewed`.
- Workbook and CSV synchronised.

## Remaining limitations

These are research limitations, not release blockers:

- purposive ten-case sampling
- heavy reliance on judicial records
- multiple-actor incidents compressed into one incident row
- uneven public availability of provider-side metadata and forensic provenance
- no inter-coder reliability study yet

These limitations are disclosed in the README and methodology.

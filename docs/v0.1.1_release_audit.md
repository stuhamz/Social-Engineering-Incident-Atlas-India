# v0.1.1 Thirty-Case Release Audit

Audit date: **26 August 2026**

## Scope

This audit covers the twenty expansion records `SEIAI-0011` through `SEIAI-0030` and their integration with the original ten-case v0.1.0 pilot.

The resulting dataset contains **30 reviewed incident records**.

## Audit checks

Each expansion record was rechecked for:

- source identity and procedural posture
- incident amount and date where the source stated them
- primary and secondary attack category
- initial contact channel and impersonated identity
- social-engineering mechanism flags
- evidence-presence flags
- distinction between original victim-facing operators and downstream financial/telecom actors
- attribution basis and attribution strength
- allegation/finding language
- financial amounts that should remain unnormalised because of source conflict or foreign currency
- privacy minimisation and unnecessary identifier reproduction

The repository was also scanned for long numeric identifiers, phone/email patterns, and account-number-like strings.

Two long numeric values remain in the structured public files because they are **FIR C.R. identifiers**, not personal bank, phone, or identity numbers.

## Material corrections made

### SEIAI-0016

`credential_compromise` changed from `yes` to `no`.

The source reports Aadhaar/PAN information and a mobile number being submitted to the fraudulent investment workflow. Under the Atlas data dictionary, `credential_compromise` is reserved for passwords, OTPs, PINs, or authentication secrets. Identity/KYC-data disclosure remains described in the case note.

### SEIAI-0029

The secondary `phishing` category was removed.

The adjudicatory record supports marketplace/UPI social engineering but does not establish credential harvesting, a deceptive login page, or disclosure of an OTP/PIN.

### SEIAI-0030

`forensic_examination_reported` changed from `yes` to `not_reported`.

The source reports FBI/IP data, malware-related findings, searches, and seized digital records, but does not clearly state that a formal forensic examination was conducted.

## Source-stage observations

The 30-case set is heavily weighted toward fact-rich bail orders. This is a retrieval property of the current validation set, not a claim about the universe of Indian social-engineering cases.

A formal statutory consumer adjudication is retained as Tier T1 material for `SEIAI-0029`; `methodology/source_quality.md` now makes explicit that T1 can include reasoned formal adjudicatory orders, while source stage remains separately recorded.

## Schema stress-test observations

Several fields remain sparsely available in public records:

- chain-of-custody discussion
- electronic-evidence authentication discussion
- platform-provider records
- IP/login evidence
- explicit reconnaissance evidence
- exact accused count

This is not treated as a reason to infer missing information.

The 30-case review also strengthens the case for considering, before v0.2:

1. an **actor-level companion table**, because one incident row can compress victim-facing operators, mule-account actors, cash-out actors, and alleged organisers;
2. a **source-claim companion table**, because one judicial order can contain prosecution allegations, defence claims, victim accounts, and judicial observations with different evidentiary status.

No such schema expansion is made in v0.1.1. The present release remains backward-compatible with v0.1.0.

## Privacy audit

The public research records do not intentionally reproduce phone numbers, bank-account numbers, email addresses, home addresses, or government-ID numbers from the underlying source documents.

Party names are retained where necessary to identify public source titles.

## Validation result

After the audit:

- 30 populated case records
- 30 records marked `reviewed`
- validator: **0 errors**
- validator: **0 warnings**

The v0.1.1 dataset is suitable for public release as a **30-case expanded methodology/schema-validation set**.

It remains unsuitable for estimating national prevalence, state rankings, average losses, relative scam frequency, demographic risk, or conviction rates.

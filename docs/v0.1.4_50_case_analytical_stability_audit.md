# v0.1.4 50-Case Analytical Stability Audit

**Audit date:** 2026-08-26  
**Scope:** 50 reviewed incident records, 148 reviewed actor-role records, 57 registered sources, 69 screening candidates.

## Release recommendation

**Do not publish/tag v0.1.4 until this analytical audit is incorporated into the release documentation.**

The audit found no structural or referential data failure requiring the 50-case dataset to be rebuilt. It did find several important sampling and interpretation limits that should be stated explicitly before the release becomes the public reference version.

## 1. Structural and referential stability

- Required incident fields missing: **0**
- Actor source-to-case mismatches: **0**
- Primary-source-to-case mismatches: **0**
- Included screening candidates map one-to-one to all 50 cases: **yes**
- Existing structural validators: **0 errors, 0 warnings**

**Conclusion:** the relational structure is stable enough for release. No breaking schema change is indicated by the 50-case audit.

## 2. Source-stage concentration

Primary-source stage:

| Source stage | Cases | Share |
|---|---:|---:|
| Bail order | 33 | 66% |
| Appellate judgment | 9 | 18% |
| Final judgment | 4 | 8% |
| Interim order | 3 | 6% |
| Procedural order | 1 | 2% |

**33 of 50 cases (66%) use bail orders as the primary source.**

This matters because source stage changes what is visible. In this corpus:

- bank evidence is reported in **100% of bail-order cases** versus **76% of non-bail cases**
- chat/message evidence is reported in **82% of bail cases** versus **29% of non-bail cases**
- electronic-evidence authentication is discussed in only **3% of bail cases** versus **41% of non-bail cases**
- integrity issues are discussed in **3% of bail cases** versus **18% of non-bail cases**

**Interpretation:** apparent evidence frequencies cannot be treated simply as properties of cybercrime investigations. They are partly properties of the judicial documents selected.

## 3. Single-source dependence

- **47 of 50 cases (94%) have exactly one registered source.**
- Only **3 cases** currently have more than one registered source.
- All 50 primary sources are T1 judicial/formal adjudicatory material.

A single high-quality judicial source can support a reviewed reconstruction, so this is not a validity failure. But it limits independent corroboration and should be disclosed.

**Recommendation for Cases 51 onward:** seek a second independent or complementary public source where reasonably available, especially for bail-stage cases and any case supporting a strong substantive claim.

## 4. Geographic and temporal concentration

- Delhi: **14/50 (28%)**
- Haryana: **9/50 (18%)**
- Delhi + Haryana together: **23/50 (46%)**
- Incident year 2025: **21/50 (42%)**

The Atlas now spans 20 state/UT labels, but the distribution remains strongly retrieval-driven.

## 5. Attack-category versus source-stage confounding

The corpus contains **17 primary attack categories**, but **10 of 17 categories appear in only one source stage**.

Examples:
- all 8 `digital_arrest` cases are bail-order cases
- all 5 `job_fraud` cases are bail-order cases
- both `family_impersonation` cases are bail-order cases
- all 3 `social_media_impersonation` cases are bail-order cases
- both `tech_support_fraud` cases are bail-order cases

**Consequence:** comparisons such as “digital-arrest cases contain more bank evidence than bank-impersonation cases” would currently mix attack-category effects with source-stage effects.

This is one of the most important constraints for any paper using the Atlas.

## 6. Actor layer: the central analytical result

Actor-role records:

| Role layer | Rows |
|---|---:|
| Victim-facing | 53 |
| Financial | 51 |
| Technical | 19 |
| Hybrid | 17 |
| Organisational | 5 |
| Unknown | 3 |

For victim-facing roles:
- **48 of 53 (91%)** are `unclear` or `not_assessed`.

For financial roles:
- **44 of 51 (86%)** have at least `limited` attribution.
- **27 of 51 (53%)** are `moderate` or `strong`.

There are **36 cases** containing both a victim-facing and financial actor layer. Using a conservative three-level comparison (`moderate/strong` > `limited` > `unclear/not_assessed`):

- financial-layer attribution is stronger in **29/36 cases (81%)**
- the layers are equal in **7/36 cases**
- victim-facing attribution is stronger in **0/36 cases**

This is a genuine and potentially publishable descriptive pattern in the corpus.

**But it is not a national prevalence estimate.** The pattern may partly arise because court/bail records disproportionately expose bank-account and transaction evidence while leaving the original caller or platform operator unresolved.

## 7. Do not treat attribution basis and attribution strength as independent variables

The actor table shows that `multiple_independent_sources`, device forensics, financial records and similar bases frequently accompany stronger attribution.

However, the Atlas attribution framework itself uses evidentiary multiplicity and linkage quality to assign strength.

Therefore:

> **Do not publish a statistical claim that a particular attribution basis “causes” or independently predicts stronger attribution using the present coded variables.**

That relationship is partly built into the coding rule.

The variables remain useful descriptively and for case comparison.

## 8. Sparse fields

Selected availability:

| Field | Available / affirmative cases |
|---|---:|
| Incident start date | 35/50 |
| Incident end date | 28/50 |
| Known account count | 17/50 |
| Forensic examination reported = yes | 6/50 |
| Electronic-evidence authentication discussed = yes | 8/50 |
| Chain of custody discussed = yes | 1/50 |
| Evidence-integrity issue reported = yes | 4/50 |
| Accused count populated | 1/50 |

### Field decisions

**Keep despite sparsity**
- forensic examination
- electronic-evidence authentication
- chain of custody
- evidence-integrity issues
- reconnaissance fields
- known account count

Their rarity can itself be analytically meaningful, and the fields have clear conceptual value.

**Review before v0.2**
- `accused_count`

It is populated in only **1 of 50 cases** and is not central to the research question. Either establish a consistent recoding rule and backfill it or deprecate it in the next breaking schema version.

Do not remove it inside v0.1.4.

## 9. What must change before the GitHub release

The data itself does **not** need another case-by-case migration before release.

Before publishing v0.1.4:

1. Add this analytical stability audit under `docs/`.
2. Strengthen README limitations with the exact source-stage, single-source and geographic concentrations.
3. State explicitly that evidence-frequency comparisons are source-stage sensitive.
4. State explicitly that the financial-vs-victim-facing attribution pattern is descriptive of this corpus, not a prevalence estimate.
5. Add `accused_count` to the pre-v0.2 schema-review list.
6. Keep `source_claims.csv` deferred. The 50-case audit still does not show a need to add that annotation burden before the actor layer is exploited analytically.

## 10. Retrieval priorities for Cases 51–75

Do not optimize for count.

Prioritize:
1. non-bail final/appellate sources for categories currently represented only by bail orders;
2. cases outside Delhi and Haryana unless they add unusual evidentiary value;
3. second-source corroboration for bail-stage incidents where feasible;
4. underrepresented attack categories;
5. records with provider metadata, forensic extraction, authentication, integrity or chain-of-custody discussion;
6. cases that can test whether the financial-versus-victim-facing attribution gap persists under different source stages.

## Bottom line

The 50-case Atlas is structurally stable.

The audit does **not** justify another schema redesign.

It does justify stronger disclosure of sampling and source-stage effects before v0.1.4 becomes the public reference release.

The most important emerging research result is the repeated separation between **financial association/attribution** and **victim-facing operator attribution**, but the corpus is not yet designed to support national-frequency claims about that gap.
